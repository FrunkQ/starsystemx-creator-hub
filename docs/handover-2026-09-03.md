Owner, 2026-09-03: *"On the admin login — lets have a bunch of data on usage — growth, etc. Not the

downloads, different users, most popular maps/user, etc. Just a standard tranche of… memory used —

**What already exists to count:** `systems.download_count` (a bare counter, no history),
`upload_events` (written on SUCCESS only: novel/total hashes, bytes, is_update, flagged),
`assets.byte_size`, `systems.source_bytes`, `hearts`, `reports`, `creators.created_at`,
`systems.published_at`. **What is missing:** per-download history, distinct visitors, failures.

**Proposed shape — build it, and record the privacy decision as D-20:**

1. **Migration 0014.** `download_events(id, system_id, visitor_hash char(64), created_at)` indexed
   on `created_at` and `(system_id, created_at)`. `visitor_hash = sha256(day + salt + ip + ua)` with
   the salt a Worker secret and the day in the hash, so a visitor is distinct within a day and
   unlinkable across days. **Never store an IP.** Write one row per download in
   `src/routes/api/download/[slug]/+server.ts` beside the existing counter (keep the counter: it
   is what the cards sort by).
2. **Record refusals.** Add `outcome text not null default 'ok'` and `reason text` to
   `upload_events`, make `creator_id` nullable, and write a row on every refusal from
   `src/routes/api/upload/+server.ts` with the refusal code (the set is: account, bad-asset-type,
   bad-json, banned-asset, cooldown, daily-limit, gm-content, hash-mismatch, ingest-failed,
   no-attestation, no-file, not-a-save, not-yours, sign-in, strip-failed, too-big, too-many-assets,
   unreadable, zips-off). "Bad uploads" is then a query, not a guess.
3. **Aggregate in SQL, not in the Worker.** Follow `db/migrations/0004_counters_rpc.sql`: one RPC
   per panel (`stats_growth(weeks)`, `stats_top_maps(days, limit)`, `stats_storage()`,
   `stats_failures(days)`). Supabase is reached over HTTP; pulling rows to count them will not scale
   and will time out on Workers.
4. **`/admin/stats`**, linked from the admin nav in `src/routes/+layout.svelte`. Panels: growth
   (creators, maps published, downloads, distinct visitors per week, 12 weeks); most popular maps
   and creators (downloads, hearts, 7/30/all); storage (sum of asset bytes + bundle bytes, per
   creator, against the R2 free tier of 10 GB); failures by code; review queue depth and oldest
   pending; open reports. Inline SVG sparklines — the page rule is no chart library, no webfonts.
5. **No email digest** until SMTP exists (section 6).

## 7. Traps that cost real time — do not re-hit

- **Bash mangles backslashes in this environment.** `'\\'` arrives as `'\'`, `\n` becomes a
  newline, and a **parse error anywhere in the command aborts the whole command** — heredocs earlier
  in the same command never run, silently. Use the Write tool for any file containing a backslash,
  and never put a backslash in a trailing `grep`.
- **Supabase row types must be `type` aliases, never `interface`**, or every query degrades to
  `never` while still compiling. `select('*')` beats a long select string (the type-level parser
  gives up). Run `npx svelte-kit sync` before believing svelte-check.
- **On Workers, `response.headers.set()` on a response from `resolve()` fails SILENTLY.** Clone the
  Response with new Headers. `src/hooks.server.ts` shows the pattern.
- **`ASSETS` is REQUIRED for a Worker with static assets** (the adapter calls `env.ASSETS.fetch`),
  which is why the R2 bindings are `HUB_ASSETS` / `HUB_BUNDLES`.
- **Local dev has no `platform.env`.** Any page that touches Supabase is blank on `npm run dev`.
  Verify on the deploy.
- **Cloudflare edge-caches API responses** (`Age:` header). Keep `max-age` short on anything a
  client reads as truth; append a query string to bust it while testing.
- **Open Graph needs absolute URLs.** Build them from `site.url`, never relative.
- **Two readers of one field can mask each other.** The pills read `t.key` correctly while the
  per-node reader filtered for strings, so tags were empty for a week with the page looking right.
  When one consumer of a field works, that is not evidence the others do.
- **The engine's facts, measured on real saves, not the type unions:** `kind` is only
  `body | construct | barycenter`; `roleHint` on real data is `star, planet, moon, belt, ring,
  station` and null on barycentres; tags are `{ key, value }` objects; a snippet is the node minus
  `image`, `model`, `gmNotes`.
- **CRLF warnings on commit are normal** (autocrlf) — do not "fix" line endings.
- **supabase-js never throws on a failed write; it returns `{ error }`.** An unchecked
  `await sb.from(...).upsert(...)` that fails is a silent no-op. And an upsert's `onConflict` must
  name the table's REAL primary key or PostgREST refuses it. The generated cover showed on the
  first page view and on no view after — the link row had never landed (0.7.1). Check `error` on
  every write that matters, and `tests/schema.test.ts` pins conflict targets to the migration text.
- **Look at the live page TWICE.** A first view can be right for reasons that do not survive a
  second one (approved-by-construction, a warm cache, a backfill that ran once). One green curl is
  not verification.
- **Never assume the engine has a consumer for what the hub emits.** Copy JSON existed for a week
  with no paste target. Grep the engine before promising a round trip.

## 8. How to verify a deploy

1. Push. Cloudflare builds in about a minute or two. Poll with a marker string:
   `curl -s <live page> | grep -c "<something only the new build renders>"` in a background loop.
2. Open the live page in the Browser pane (`preview_start` with the URL). **The pane is often
   hidden — screenshots come back black.** Verify with `read_page`, `find`, and `javascript_tool`
   instead; ask the owner to display the pane if you need a picture.
3. Clipboard behaviour is testable without permissions: wrap `navigator.clipboard.writeText` to
   capture the text, click the control, read it back.
4. Console errors: `read_console_messages` with `onlyErrors`.
